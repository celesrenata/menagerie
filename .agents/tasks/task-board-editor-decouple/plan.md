# Implementation Plan — Decouple the Task Board / task lifetime from the editor tab

Implements `design.md` revision 3 (final review `design-review.md`: 0 HIGH, no hard-block conditions). This is a single cohesive change: one production file (`src/core/webview/ClineProvider.ts`), one command file (`src/activate/registerCommands.ts`), the cleanup-protocol model script, and tests. The design is authoritative; this plan sequences it and bakes in the two mechanical corrections the final review flagged.

## Grounding verified against source (do not re-derive)

- `src/core/task/TaskRegistry.ts` — exposes `current` getter, `length`, `taskIds`, `getById`, `getAll`, `getRunning`, `hasRunning`, `setCurrent`, `push/pop/remove/replace`. **There is NO `getCurrentTaskId()` and NO `getCurrentTask()`.** → Correction #1: the reap guard must read `this.getCurrentTask()?.taskId` (provider accessor at `ClineProvider.ts:3324`, returns `this.taskRegistry.current`) or `this.taskRegistry.current?.taskId`.
- `ClineProvider.ts` `taskCreationCallback` (~435): `onTaskCompleted` is `async`, does the history `status: "completed"` write, then `this.emit(RooCodeEventName.TaskCompleted, …)`. `onTaskAborted` is `const onTaskAborted = () => this.emit(RooCodeEventName.TaskAborted, instance.taskId)` — **synchronous, NO status write.** → Correction #2: the completed path appends the reap after `await` status-write + `emit`; the aborted path appends `void this.dispose()` after `emit` and assumes `"aborted"` is already persisted by the abort flow (it is NOT written in this listener).
- `ClineProvider.ts` constructor (~360): `(context, outputChannel, renderContext: "sidebar" | "editor" = "sidebar", contextProxy, mdmService?)`. `private view?: WebviewView | WebviewPanel` at ~217.
- `resolveWebviewView` (~1037): `inTabMode = "onDidChangeViewState" in webviewView`; message listener + view-state/visibility listeners already pushed onto `this.webviewDisposables`; **`onDidDispose` is registered on `this.disposables`** (~1135–1146) — must move to `webviewDisposables`. Tab branch of `onDidDispose` calls `await this.dispose()`; sidebar branch calls `this.clearWebviewResources()`.
- `dispose()` (~848) order: drain registry (`evictCurrentTask`/`removeClineFromStack`) → `if (this.view && "dispose" in this.view) this.view.dispose()` → `clearWebviewResources()` → drain `this.disposables` → `activeInstances.delete(this)`. Idempotent via `_disposed`.
- `clearWebviewResources()` (~824) drains `messageQueue` + `webviewDisposables`.
- `openClineInNewTab` (`registerCommands.ts` ~222): `new ClineProvider(context, outputChannel, "editor", contextProxy, mdmService)`, creates `WebviewPanel`, `await tabProvider.resolveWebviewView(newPanel)`; its own `newPanel.onDidDispose` only calls `setPanel(undefined, "tab")` (never aborts).
- `createParallelTaskRuntime` (`ClineProvider.ts` ~3395): `new ClineProvider(this.context, this.outputChannel, "editor", this.contextProxy, this.mdmService)`, `resolveWebviewView(panel)`, `createTask(..., { parallelWorker: true, startTask: false, … })`.
- `taskBoard.ts` `collectTaskBoard()`: maps `ClineProvider.getAllInstances()` → `provider.getCurrentTask()`, one row per provider, filters `undefined`. No change needed; add a regression test.
- `scripts/check-task-cleanup-protocol.ts`: only hardcoded total is `${result.landmarks}/8` in the final `console.log`; `expectedActions`/`expectedLandmarks` are arrays; `missingActions`/`missingLandmarks` compare against those arrays dynamically. → single literal edit `/8`→`/9` plus array additions.
- Test harness (`src/core/webview/__tests__/ClineProvider.spec.ts`): `mockWebviewView` is a sidebar mock (no `onDidChangeViewState`, `onDidDispose` immediately invokes its callback). Popout/worker tests need a **panel mock** with `onDidChangeViewState` present (so `inTabMode` is true) and a **controllable** `onDidDispose` (capture the callback, don't auto-invoke).
- Package commands: build/types `pnpm --dir src check-types`; tests `pnpm --dir src exec vitest run <path>`; lint `pnpm --dir src exec eslint --prune-suppressions --max-warnings=0 <file>`; model check `pnpm lifecycle:model-check` (chains `cleanup-protocol:model-check` = `tsx scripts/check-task-cleanup-protocol.ts`).

Each item below leaves the codebase buildable. Order is dependency-driven.

## Notes / assumptions

- No `.changeset` or `CHANGELOG` edits (AGENTS.md).
- No `taskLifecycle.ts` reducer or `VALID_TASK_STATUS_TRANSITIONS` change — detach performs no `HistoryItem` mutation; the only model edit is in `check-task-cleanup-protocol.ts`.
- `editorViewRole` is threaded via a `setEditorViewRole` setter rather than a new constructor parameter, to avoid changing constructor arity relied on by the spec and other `new ClineProvider(...)` callers. If the implementer prefers an options bag, that is equivalent but touches more call sites.
- E2E (`apps/vscode-e2e`) is OUT OF SCOPE unless the unit + model layers cannot prove a behavior; the design permits one optional two-case smoke test (popout close keeps task; worker close ends worker) but the lower layers above cover every assertion, so do not add E2E first.
- If item 8's re-open needs a board/webview trigger message, that is the only reason to touch `packages/types` / `webviewMessageHandler`; otherwise `openTaskInNewTab` is command-only.
