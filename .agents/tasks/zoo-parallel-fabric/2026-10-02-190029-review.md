# Zoo parallel-fabric: condensing-model port + reader-tier/auto-reader hardening

The branch adds three independent workstreams. **A** clones the existing `enhancementApiConfigId` round trip under `condensingApiConfigId`, letting context condensing/summarization run on a chosen reader model instead of the orchestrator's own `this.api`; default-unset is byte-identical to today. **B-i** is a labeling + test-hardening change that pins the already-correct reader/reasoner tier mapping (project-reader→reader/9B field, project-research + code→reasoner/27B field) without touching routing logic. **B-ii** relaxes the `addSharedDocumentReader` auto-reader trigger so a bounded, read-only reader worker fires for 2–3-worker mixed-mode fan-outs that share a doc, guarded so it never pushes past the 4-worker cap.

Watch for: nothing blocking. The branch also carries a separate, prior task's commits (the `omniroute-integration` FEAT-003/004/005 OmniRoute tier-dropdown work) ahead of these three — out of scope here, flagged as bundling context (confirmed via git log). The condensing third call site (`attemptApiRequest`) is wired identically to the two threading-tested sites but is not itself threading-tested (likely — the two tested sites plus tsc cover the pattern).

**Verdict**: APPROVED

## High-level view

Workstream A's design risk is low because it mirrors a fully-wired reference feature end to end: schema → `ExtensionState` → `ClineProvider` round trip (all three enhancement sites matched) → generic `updateSettings` persistence (no dedicated webview message, deliberately avoiding a second un-cached save path) → a `Task` helper that builds the handler. The one piece of real logic is `getCondensingApiHandler()`'s single caching rule: cache only the _built_ handler keyed by config id, always return live `this.api` on the own-model path (never cache it), re-resolve only on id change. That rule is what keeps default-unset byte-identical and keeps a mid-task config change from going stale; it is directly unit-tested with identity assertions.

The SettingsView control follows the AGENTS.md cachedState rule: it binds to the `cachedState`-sourced `condensingApiConfigId` prop and `setCachedStateField`, never posts on change, and flows into the `handleSubmit` payload as `condensingApiConfigId ?? ""`. The empty-string sentinel (not `undefined`) is the deliberate clear-to-default form so a previously-saved value can be reset through the message pipeline.

B-i changes only doc comments and four en/settings.json label strings plus regression-locking test assertions; `READER_MODES` membership and `roleDefault` logic are untouched, and a test explicitly pins `project-research` as a non-member so a future edit can't silently route it to the 9B field.

B-ii's trigger broadens from "exactly 3 code workers, ≥2 sharing a doc" to "≥2 and <4 workers, any mode, ≥1 referencing a doc." The `specs.length >= 4` early return is the sole cap enforcer and is tested; the auto-reader keeps its read-only, excerpt-only, no-`read_file` contract.

The AGENTS.md gates hold: no `.changeset` or CHANGELOG edits, `src/eslint-suppressions.json` unchanged (the `--prune-suppressions` run only rewrites whitespace with no count change), and `taskLifecycle.ts` is untouched so the lifecycle gate does not apply.

### Condensing-handler resolution and the single caching rule

`Task.getCondensingApiHandler()` is the single resolution point all three condensing sites delegate to, which is where the "default == today" invariant lives. The flow: deref the provider (dead ref → `this.api`), read fresh `condensingApiConfigId` + `listApiConfigMeta` from `provider.getState()`, and if the id is unchanged from `this.condensingApiHandlerConfigId`, return the cached built handler or live `this.api` — no `getProfile`, no rebuild. On a changed id it records the new id, then: unset/empty or id-not-in-`listApiConfigMeta` → clear the cache slot and return `this.api`; otherwise `getProfile({ id })`, and if the profile has no `apiProvider` → `this.api`, else cache and return `buildApiHandler(providerSettings)`. A `try/catch` logs per-call via `provider.log(...)` and falls back to `this.api` on any throw.

Two things make this correct rather than merely plausible. The `listApiConfigMeta` membership check runs _before_ `getProfile`, which is mandatory because `ProviderSettingsManager.getProfile` throws on a missing id — the guard converts a deleted-profile id into a silent fallback instead of an exception at a condensing site. And `this.api` is never stored: the own-model branch returns the live reference each call, so a mid-task `updateApiConfiguration()` (which rebuilds `this.api`) is always reflected. The unit suite asserts these with object identity (`toBe(task.api)`) across unset, missing-id (no `getProfile` call), valid-built, no-`apiProvider`, throw-and-log, dead-ref, and the mid-task A→A-cached→B-rebuild→cleared sequence.

### Condensing round trip and the deliberate generic-save path

The setting round-trips through the three `ClineProvider` locations that `enhancementApiConfigId` uses (`getStateToPostToWebview` destructure + returned object, and `getState`'s returned object as a bare `stateValues.condensingApiConfigId` pass-through with no `?? ""` default), so a saved control doesn't revert visually. Persistence rides the generic `updateSettings` loop rather than a dedicated `{ type: "condensingApiConfigId" }` message — the design's one intentional divergence from the enhancement reference, because the enhancement message exists only to support an immediate-save Prompts control, which is exactly the pattern AGENTS.md warns against for a cachedState-bound control. Tests confirm the generic path stores both a chosen id and the `""` clear sentinel, the getState/getStateToPostToWebview round trip for set and unset, and that import restores the value (not stripped by the export omit list).

### Reader/reasoner tier labeling (B-i)

No routing logic changed. `READER_MODES` stays `{ project-reader }`; the diff expands the doc comments to spell out the two-field→three-tier intent (reader field = LOW/9B, used only by project-reader; reasoner field = HIGH/27B, shared by code and project-research) and relabels the four OmniRoute en/settings.json strings to read as "Low reader (9B)" / "High reader (27B) - coder + research." The spec hardens `parallelWorkerRouting.spec.ts` with explicit assertions locking project-reader→reader, project-research→reasoner, code→reasoner, unset→parent fallback, and `READER_MODES.has("project-research") === false` — the last pins the intent that project-research is deliberately not a reader-field member, so a later edit can't silently flip it to the 9B field.

### Auto-reader trigger relaxation and the 4-cap guard (B-ii)

The early return changed from `specs.length !== 3 || specs.some(mode !== "code")` to `!readerAvailable || specs.length < 2 || specs.length >= 4`, and the shared-doc selection threshold from `count < 2` to `count < 1`. Because the counts map only ever holds entries with count ≥ 1, the new threshold effectively means "any referenced doc qualifies," with the sort-by-count retained so the most-shared doc still wins. The `specs.length >= 4` branch is the sole cap enforcer: `parallelTasksSchema.parse` (min 2, max 4) runs on the requested tasks before `addSharedDocumentReader` appends, so a 4-worker request is left untouched rather than pushed to 5 (which would throw). The generated preamble is now count-agnostic (`${specs.length} sibling workers`), and the read-only / excerpt-only / no-`read_file` instruction and the realpath/escape/size guards are intact. Tests cover 2-worker, mixed-mode (code + project-research), single-referencer, and the 4-cap-no-append edge, each asserting the appended worker is `project-reader` and keeps the no-`read_file` instruction.

### SettingsView cachedState binding

The picker in `ContextManagementSettings` reads the `condensingApiConfigId` prop (sourced from SettingsView's `cachedState` destructure) and writes via `setCachedStateField("condensingApiConfigId", value === "-" ? "" : value)`, with no `vscode.postMessage` on change and no live `useExtensionState()` read. SettingsView passes the field down and adds `condensingApiConfigId: condensingApiConfigId ?? ""` to the `handleSubmit` payload. The `.map` callback is typed `{ id: string; name?: string }` to avoid an implicit-any on the `any[]` prop. The revert-on-discard test is the one that actually proves the buffer: it selects a profile (cachedState shows the id, no message posted), discards, and asserts the control re-initializes to the live `""` and no `updateSettings` carried the discarded id. The i18n keys (`condensingApiConfiguration.{label,description,useCurrentConfig}`) pre-exist in en/settings.json.
