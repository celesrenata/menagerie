# OmniRoute failure-fix (A–E) + per-request cost-tier dropdown

Five diagnosed OmniRoute failures are fixed across three repos and a new `$..$$$$$` cost-tier
dropdown is wired end-to-end into menagerie. Failure B (context off-by-one) is an OmniRoute
model-capability-override reconciliation applied live; Failure C (system-message displacement) is a
source fix routing self-hosted strict-template providers through system-first memory merge; Failure D
(stale tier-5 model id) is a routing-policy edit applied live; Failure A (empty-502) is handled as
needs-runtime-verification with new observability rather than a guessed fix, because the retained
logs do not support the injection hypothesis; Failure E (parallel non-spreading) is a downstream
effect of A/C and is verified resolved at runtime. FEAT-005 adds `X-OmniRoute-Tier` resolved purely
on the OmniRoute side and sent per-request from menagerie, bound beside the YOLO control.

Watch for: an uncommitted whitespace-only reformat of `src/eslint-suppressions.json` leaves the
menagerie working tree dirty (confirmed — cosmetic, no suppression-count change); the FEAT-005
menagerie branch bundles an unrelated combo-id catalog fix and a `src/package.json` version bump
(confirmed — documented and tested, but outside the failure-fix scope).

**Verdict**: APPROVED

## High-level view

Failure B was reconciled by adding the balanced variant to the `omniroute-routing.py` `layouts` dict
and re-applying the model-capability-override PATCH; the live overrides and `/v1/models` both read
back `vllm/qwen3.8-27b-nvfp4 = 131072/98304` and `…-balanced = 131072/65536`, and esnixi's
`vllm.nix`/`vllm-switch.py` were left untouched for B as required.

Failure C adds `vllm, ollama-local, ollama, llama-cpp, llamacpp` to
`BUILTIN_PROVIDERS_SYSTEM_MUST_BE_FIRST`, so cache-safe memory injection merges into `messages[0]`
instead of splicing a mid-array system message. The tests assert, per provider, a single system
message at index 0 with the memory merged in and zero system messages at any later index, plus a
regression guard that non-strict providers keep the old mid-array splice.

Failure D changes tier-5's `openai/gpt-5.6` to the resolvable `openai/gpt-5.6-terra` and re-applies
the tiered policy; live combos now carry zero bare `openai/gpt-5.6` references and 22 `-terra`
references, and `-terra` is advertised in `/v1/models`.

Failure A's observability adds a three-state `mem=true|false|?` field to the empty-output 502
diagnostic line, fed by a new typed `memoryInjected` flag that flips only when memory text was
actually merged (not tool injection). The diagnosis correctly does not attribute the empty-502 class
to injection: the two 502s seen during probes are transition-race (`fetch failed` / `terminated`),
and the hypothesis stays re-openable through the new field.

Failure E is verified at runtime: two concurrent `hybrid/code` requests landed on two distinct
members (esnixi-5090 + m5max), reader requests resolve to a 9B reader (not qwen-27b), code requests
resolve to GLM (never MLX), and no System-first 500 recurred. The optional m5max `maxConcurrent`
raise was correctly left at 1 because its 2-concurrent probe inflated latency 6–12x.

FEAT-005 resolves `X-OmniRoute-Tier` purely in `requestControls.ts`/`engine.ts` by reusing the
existing `classifyTier` bands (no hardcoded model lists) with the ceiling held even through the
empty-pool self-healing fallback. menagerie models the tier as a global setting with a shared schema,
round-trips it through `getState`/`getStateToPostToWebview`, injects it onto the active profile only
when OmniRoute (and strips it otherwise), and emits the header only for an OmniRoute profile with an
integer 1–5 tier. The dropdown lives in the chat toolbar beside AutoApproveDropdown and immediate-saves
via `updateSettings`, which is the correct pattern there (not SettingsView, so the cachedState buffer
rule does not apply).

### Failure A — observability without a guessed fix (FEAT-004)

`open-sse/utils/diagnostics.ts` adds `mem=true|false|?` to the `[MALFORMED-200]` line, with a
deliberate three-state distinction (`null`/`?` = not reported, distinct from explicit `false`).
`memorySkillsInjection.ts` returns a typed `memoryInjected: boolean` that flips to `true` only when
`injectMemory()` actually merged retrieved memory text — tool-only injection does not flip it — and
`chatCore.ts`'s single call site passes it through. The diagnosis is evidence-grounded: all 33
retained empty-502 call logs had `MEM=False`, the real 502s are `ECONNREFUSED`/transition races, and
the two 502s observed during probes were classified as `fetch failed` and switcher `terminated`, not
empty-output and not System-first. The injection hypothesis is left re-openable through the new field
rather than dismissed. Verified via the diagnostics and memory-skills node tests.

Runtime call-log evidence: two concurrent `hybrid/code` requests resolved to `ds4-glm53@stabulous-m5max`

### FEAT-005 — X-OmniRoute-Tier resolver and the dropdown round trip

`resolveRequestTier` parses the header to an integer 1–5 (else `undefined` so stored config stands),
threaded through `resolveRequestAutoControls` and `resolveAutoStrategy` into `AutoComboConfig.tierCeiling`.
`engine.ts` maps the 1–5 ceiling onto the existing free/cheap/premium bands via the shared
`classifyTier`/`PROVIDER_TIER` (no hardcoded model lists) and filters candidates before scoring; the
ceiling is deliberately preserved through the empty-pool self-healing fallback (only self-healing/pool
exclusions are relaxed, never the tier band). The node test proves parse validation (rejects
0/6/-1/2.5/"x"/empty/non-string), tier-3 excludes a premium-only pick over 50 deterministic runs,
tier-1 admits only free, and an absent ceiling keeps a premium candidate reachable. Verified: the
services node-test glob passes (75 incl. 6 new) and `typecheck:core` is clean.

On menagerie, `omniRouteTier` is a global setting backed by a shared `omniRouteTierSchema`
(`z.number().int().min(1).max(5)`), added to `ExtensionState` and mirrored on the OpenAI
provider-settings schema so it rides `ApiHandlerOptions` to the request path. `ClineProvider.getState()`
returns it with `undefined` = server-default and injects it onto the active profile only when
`isOmniRoute`, stripping it from any other profile; `getStateToPostToWebview()` destructures and
returns it. `omniRouteRequestHeaders()` is the single place the tier→header mapping lives and emits
`X-OmniRoute-Tier` only for an OmniRoute profile with a valid integer 1–5. `OpenAiHandler` merges it
into `defaultHeaders`. The `OmniRouteTierDropdown` renders `$..$$$$$` (+ Default) beside
`AutoApproveDropdown` in `ChatTextArea`, visible only for OmniRoute profiles, saving immediately via
`updateSettings` — the correct pattern for a chat-toolbar control (the AGENTS.md `cachedState` rule
is specific to SettingsView). Tests cover header set/unset/non-OmniRoute/out-of-range, the full
ClineProvider round trip (set/unset/non-OmniRoute strip), and the dropdown binding/save/clear/visibility.
Verified: webview suite 1886 pass, the four src specs 405 pass, and
`eslint --prune-suppressions --max-warnings=0` on every edited src file exits 0 (no count increase).
No `.changeset`/CHANGELOG edits in either repo.
